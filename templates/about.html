Apa itu Deterministic Finite Automaton (DFA)?
Pengantar Konsep Teori Bahasa dan Automata

Deterministic Finite Automaton (DFA) adalah mesin abstrak pada Teori Automata yang menerima atau menolak string (barisan simbol) dengan memindahkan statusnya (state) dari satu keadaan ke keadaan lain secara berurutan. DFA bersifat Deterministic karena untuk setiap state dan setiap simbol input yang diberikan, hanya ada tepat satu state tujuan berikutnya. Tidak ada ambiguitas atau tebakan dalam transisi.

Finite State (Keadaan Terhingga)
Mesin memiliki jumlah state yang terhingga. Ia tidak memiliki memori tambahan selain state yang sedang ia tempati saat ini.
Deterministic Transition
Untuk setiap karakter pada kata sandi yang diketik, arah mesin berpindah sangat pasti dan tunggal. Tidak memiliki transisi ke state kosong (epsilon).
Definisi Formal (5 Tuple)
M= (Q, Σ, δ, q0, F)
  • Q
    Himpunan Terhingga dari State
    Dalam aplikasi ini mewakili kombinasi kondisi sandi (misal q_<1,0,0,0> artinya hanya memiliki huruf kecil).
  • Σ
    Alfabet (Simbol Input)
    Himpunan karakter keyboard yang diizinkan untuk diketik, seperti huruf [a-zA-Z], angka [0-9], dan karakter khusus.
  • δ
    Fungsi Transisi
    δ : Q × Σ → Q. Fungsi yang menentukan perpindahan state dari satu state ke state lain saat mesin membaca suatu input (dapat dilihat di Log Simulasi).
  • q0
    State Awal (Initial State)
    State awal mesin (q_<0,0,0,0>), merupakan bagian dari himpunan Q, kondisi ketika kata sandi masih kosong.
  • F
    Himpunan State Akhir (Accept State)
    State penerimaan di mana string kata sandi dinilai valid (memenuhi semua kriteria kekuatan). Ditandai dengan state q_<1,1,1,1>.
Penerapan DFA Pada Validasi Kata Sandi
Cara Kerja Sistem Keamanan Validator Ini

Aplikasi ini memodelkan kata sandi yang kuat dengan sebuah DFA berstatus banyak (State direpresentasikan dengan vektor kondisi: <lower, upper, digit, special>). Setiap kali Anda mengetik satu karakter:

  1. Aplikasi mengambil huruf yang baru Anda ketik.
  2. Melakukan pengecekan kelas karakter (huruf, angka, dll).
  3. Memperbarui vektor status (dari 0 menjadi 1 pada indikator bersangkutan).
  4. Transisi terjadi dan tercatat di Log Simulasi.
  5. Apabila terdapat spasi, mesin langsung berpindah ke Trap State, yang mana membuat string apapun ditolak.
Catatan: Meskipun DFA yang digunakan di atas belum menghitung panjang karakter pada proses logikanya (mencegah ledakan jumlah state secara eksponensial), validasi panjang karakter (8-32) ditambahkan pada tahap verifikasi akhir saat mesin mengevaluasi Accept State.
